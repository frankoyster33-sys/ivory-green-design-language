# 跨媒介制作指南

把米白、森林绿、衬线标题与疏朗节奏迁移到不同媒介。尺寸与字号是制作起点，应随内容密度、观看距离、语言和交付要求调整；不要把网页像素直接换成 PPT 点数，也不要把同一张画布拉伸成所有比例。

## 共用视觉骨架

- 大面积背景使用白色或米白 `#F9F4EC`；森林绿 `#134436` 用于标题、关键区域与深色反白面板。
- 正文深墨绿 `#203D34`，次级文字 `#50665C`，细线 `#D7DFD3`。操作主色 `#006442`，黄色 `#FFE552` 只标记少量关键数字、位置或提示。
- 标题衬线、正文无衬线。英文标题可用 Georgia；中文标题优先选择可用且获准使用的宋体类字体，如 Songti SC、Noto Serif SC。中文正文选择 PingFang SC、Microsoft YaHei 或 Noto Sans SC。明确实际使用的字体与替代方案，不承诺接收端一定装有字体。
- 中文标题不沿用英文的负字距与全大写规则；中文长标题用自然换行，行高通常从 1.25–1.4 开始调整。
- 留白先服务分组与阅读顺序。细分隔线、短标签与对齐通常比增加卡片更有效。不要把每段文字都装入圆角容器。
- 绿色是设计选择，不代表健康、安全、可持续或审核通过。状态含义另行定义，并配文字或图标。

## 演示文稿 / PPT

**画布与网格**

- 默认宽屏 16:9；原生页面可设为 13.333 × 7.5 英寸。1920 × 1080 px 只作为预览或位图画布尺寸。
- 四周安全边距从 0.55–0.75 英寸起步；用统一左边线组织标题、正文、图表与页码。
- 单页只承担一个主要论点。需要保留的细节可移至补充页，而不是连续缩小字号。

**字号起点**

| 角色 | 建议字号 | 用法 |
| --- | --- | --- |
| 封面主标题 | 40–54 pt | 控制为 1–3 行；中文依字数调整 |
| 内容页标题 | 30–40 pt | 衬线常规字重，避免细到投影后消失 |
| 正文 / 图表标签 | 20–26 pt | 小屏演示或远距离投影需进一步放大 |
| 关键数字 | 48–76 pt | 数字与单位分层，不依靠颜色单独解释 |
| 注释 / 页码 | 12–16 pt | 只放次要信息，关键结论不能降到注释层 |

**版式家族**

1. 封面：米白底、左对齐衬线标题、简短导语、一个视觉主体。
2. 论点页：大标题 + 一句结论 + 一幅图或最多三个并列要点。
3. 比较页：相同列宽与基线；共同维度逐项对齐，差别使用文字说明。
4. 图表页：主图占主要面积，标题说明发现，图下注明单位与来源。
5. 章节页：森林绿背景、米白大字、细小编号；留足空白。

正文、形状、表格和适合编辑的图表尽量保持原生可编辑对象。不要把整页截图当作可编辑 PPT 交付。真实照片或复杂插画可作为图片，保留裁切余地。

**交付检查**：逐页渲染，检查溢出、字体替换、中文断行、图表单位与对齐；在实际目标软件复核可编辑性。只经过 PDF 预览时，应明确尚未验证目标软件中的编辑与动画表现。

## Photoshop / 海报 / 社交图片

**先确认输出用途**

| 用途 | 起始画布 | 注意事项 |
| --- | --- | --- |
| 方形数字海报 | 1080 × 1080 px | 主信息远离裁切边缘 |
| 竖版数字海报 | 1080 × 1350 px | 将内容重新排版，不拉伸方形图 |
| 全屏竖版视觉 | 1080 × 1920 px | 预留上下界面遮挡空间，并按发布界面复核 |
| 横向文章封面 | 1600 × 900 px | 为缩略图和其他裁切比例保留主体 |
| A4 印刷海报 | 成品 210 × 297 mm | 分辨率、出血、色彩空间按印厂要求设置 |

常见印刷起点为 300 ppi、四周 3 mm 出血，但这不是所有印厂的固定要求。成品边界、出血和文字安全区是不同概念。在线图片的清晰度主要取决于像素尺寸；更改 ppi 数字不会增加细节。

**排版起点**

- 安全区可从短边的 5–8% 起步。主标题通常占 2–4 行以内，副标题与说明形成清楚的字号差。
- 1080 px 宽画布可从标题 76–110 px、导语 32–44 px、次级说明 24–30 px 试排，再按最终显示尺寸检查。
- 大面积米白底搭配一个深绿信息区；黄色只点亮一个主要位置。照片本身颜色丰富时减少装饰色。
- 使用真实且相关的图像、抽象图形或有说明用途的线稿。不要用无意义纹理、叶片和光效填补空白。

**建议 PSD 分组**

```text
00_guides         参考线与安全区，导出前隐藏
01_background     纯色、纸感或必要的背景层
02_visual         图片智能对象、插画及裁切蒙版
03_heading        可编辑标题文字
04_body           导语、说明、标注文字
05_accents        色块、细线与强调元素
06_footer         必需的署名或出处，若无则省略
```

文字保持文字层，图片尽量使用智能对象，调整采用非破坏性图层与蒙版。按用途导出 PNG/JPEG 或印刷文件，并保留制作源文件。

**格式边界**：只有生成并打开检查过的真实分层 PSD，才能称为 PSD 交付。不能把 PNG 改扩展名冒充 PSD；SVG、PDF 或 HTML 也不是 PSD。工具无法生成 PSD 时，先说明能力范围，提出可编辑矢量源文件与预览图的替代方案；用户明确要求 PSD 时不要自行把替代格式视为完成。

**交付检查**：按原尺寸与缩略图查看；检查锯齿、溢字、主体裁切、透明边缘、缺失字体和图层命名。印刷版需使用指定色彩配置做软打样或样张核验，屏幕颜色不能保证纸张上的效果。

## 界面 UI / 交互网页

**布局与类型**

- 米白适合页面底色，白色适合内容区；森林绿适合关键面板。界面内容多时，优先使用清晰的行、列、分隔和分组。
- 正文从 16–18 px、行高 1.5–1.7 起步；页面标题 28–40 px；模块标题 20–28 px。小型弹窗、表单和工具栏使用更克制的标题，不复制封面巨型字号。
- 用 4 px 或 8 px 的间距节奏统一组件。圆角应有层级，例如控件 8 px、卡片 12–16 px、主要交互区 20–24 px。
- 内容宽度与断点由任务决定。长文阅读栏宜控制行长；表格、比较工具与画布可以更宽。

**交互与无障碍**

- 使用语义化按钮、链接、标签、输入框和表格。按钮描述动作，链接描述目的地；控件状态必须可被键盘与辅助技术识别。
- 文字对比度以 WCAG AA 为核查起点：一般文字 4.5:1，大字 3:1；必要的控件边界与图形信息通常需 3:1。实际计算每个前景/背景组合，不凭肉眼判断。
- 淡边框只用于装饰性分隔；若边界是识别输入框的唯一依据，应加深或提供其他明确线索。
- 主要触控目标优先设计到约 44 × 44 CSS px，并保留间距。可见焦点、错误解释、加载反馈、空状态与禁用原因一起设计。
- 错误、成功、警告和信息使用明确文案与符号；不要把所有状态都变成绿色，也不要只靠红绿区分。
- 动画通常保持短促，尊重减少动态效果偏好。不要让内容必须等待动画才能读取。
- 每个交互必须有实际用途：筛选、比较、理解关系或完成操作。展示性按钮不能伪装成功操作，演示数据要标明。

**交付检查**：桌面与窄屏、键盘操作、200% 缩放、长文本与空数据、加载失败、焦点可见性、对比度。不要仅靠静态截图声称交互或无障碍全部通过。

## 插画 / 配图 / 数据图表

- 将图像分为三类：氛围插画、解释性图示、数据图表。先确定它要帮助读者理解什么，再选择制作方法。
- 氛围插画：米白背景、深绿主形、少量黄色；可以使用轻微纸感，但缩小后应保持清晰。避免过度颗粒与装饰。
- 解释性图示：优先矢量线条、清楚的步骤编号与短标签。几何关系、方向、层级与标注需人工复核。
- 数据图表：使用真实输入和可复现绘图；保留单位、坐标轴、时间范围、来源与必要的不确定性。不要让生成式图像承担精确数值绘制。
- 连续数值使用有序明暗，类别使用可区分的颜色并加直接标签。仅有两种绿色时不能假定能表达大量类别；允许扩充经对比度和色觉检查的辅助色。
- 关键文字与数字尽量在布局或矢量工具中后加，保证可读、可改、可校对。

**交付检查**：在最终尺寸检查标注、箭头、尺度与图例；矢量文件检查可编辑性；位图检查透明底、分辨率与裁切。AI 生成的图像不能被描述为真实事件记录或检测证据。

## 长文 / 交互编辑式 HTML

- 采用连续阅读结构：小标签 → 衬线大标题 → 短导语 → 主视觉 → 清晰章节。主结论可以放入米白强调区。
- 桌面正文可从 17 px / 1.8 起步，窄屏 16 px / 1.75；段后间距约 20–22 px，章节间距约 48–64 px。
- H1 可从 `clamp(36px, 5vw, 60px)` 起步，H2 从 `clamp(28px, 3.2vw, 39px)` 起步；中文使用独立行高和字距规则。
- 图注可以比正文小，但关键判断、限制与操作说明不能缩成脚注。宽表格提供独立横向滚动，避免整页横向溢出。
- 只在有助于理解时加入折叠、切换、输入模拟或清单。计算示例明确输入、单位、假设与适用范围；不要把示意模型呈现为权威判定。
- 离线交付时检查字体回退、图片、脚本与样式是否可用；跨站嵌入时使用独立样式作用域，防止污染宿主页面。

**交付检查**：首次加载、移动端阅读、键盘顺序、打印样式、断网表现（仅当承诺离线时）、交互正确性与控制台错误。标明哪些环境已实际验证。
